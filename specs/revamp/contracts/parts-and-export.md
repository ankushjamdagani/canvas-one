# Parts and exports (RV-02g)

Saved parts (detached copies) and the JSON, SVG/PNG, CSV and Mermaid exports. [model-and-runner.md](model-and-runner.md) and [storage.md](storage.md) govern validation and versions.

## Capture and placement

Capture takes a nonempty set of selected element IDs in one authored view. Preview lists selected elements, required schema/fixture/refinement dependencies, included internal connections/relations, excluded external connections and warnings. Nothing changes until save succeeds. Include complete refinements only: selecting an owner includes its full member closure; selecting an internal member alone is allowed only if it has no unselected owner/reference dependencies, otherwise require expanding selection or cancelling. Never silently include another unrelated subsystem.

Part content is `{schema:'studio-part-content/1',elements,connections,relations,schemas,fixtures,refinements,view:{placements,groups,notes}}`. Shapes are identical to Document members, but no document/scenarios/history/runs. Include internal connections with both endpoints selected, relevant relations with all endpoints selected, full referenced schemas/fixtures and all nested referenced IDs. A deployed-on crossing or missing machine fixture/schema is a blocking dependency unless included explicitly. Unselected ordinary behavioral neighbors are excluded; exposed ports remain unconnected and a placement readiness warning explains that wiring is required. No fabricated boundary fixtures or executable stub success.

Wholly selected view groups are included; partial groups omitted with preview notice. Notes selected explicitly or attached wholly to selected elements may be included; mixed/external attachments are excluded with notice, not remapped to unrelated nodes. Use the source view's coordinates relative to the minimum selected element x/y; negative note offsets are allowed. Saved labels/configuration remain exact. Limits: <=50 elements, <=100 connections, <=100 relations, <=50 notes and <=512 KiB canonical part content, also all document nested limits. A larger selection fails before mutation and suggests smaller selection, not silent trimming.

Saved part identity `{id,revision,label,description,content}` uses revision integer starting 1; updating creates immutable next revision, never modifies an existing revision or placed copy. Count every revision toward the project part ceiling. No cross-project/team catalog in v1. Standalone transfer `{format:'system-studio-part',version:1,part}`; validate independent reference closure and byte cap before insertion. Import assigns a new library part ID and revision 1; content IDs can remain in the isolated part namespace until placement. Source provenance is descriptive, not live-linked.

Placement first builds a fresh UUID mapping for **all** independently identified members, including port/state/transition/effect/operation/schema-field/fixture/refinement/mapping/group/note IDs. Rewrite typed references using schema-owned reference descriptors, never string search (user text and literal payload strings must not change). Insert all copied model entities and dependencies plus view placements atomically into the destination working copy at selected anchor (default viewport center in canvas coordinates). Schema/fixture copies are detached even if content equal; no accidental shared editing. Validate destination total limits and all cross-references before one accepted command/undo step. Saving/exporting a part does not mutate the source document. Imported parts cannot import trusted metrics, actors, commands or scripts.

Reference-remap coverage is explicit: Note.attachedElementIds and Group.elementIds; Placement.elementId; Connection source/target elementId+portId; Relation parentId/childId/elementId/hostId/sourceId/targetId; Port schemaId/responseSchemaId; schema-field IDs; machine state IDs/initialStateId, transition from/to/eventPortId, emit and schedule-event portIds, contextSchemaId/initialContextFixtureId, responseBindings (id/callPortId/eventPortId); pipeline input/output/error schema and port IDs and validate.schemaId; decision inputSchemaId/inputPortId and case/fallback output ports; resource entryPortId; Fixture.schemaId; Refinement owner/member IDs and every portMapping outer/inner elementId+portId. Rename each definition ID once and rewrite every typed reference. Literal user payload values and labels are not references. Unknown fields already reject; coverage tests fail if a future typed reference lacks remapping.

Acceptance includes self-contained machine and pipeline parts, refined service, internal/external wiring preview, attached notes/partial groups, UUID collisions, target document near limits, save failure and one-step undo. Remap golden fixture checks every reference kind; unknown new reference fields fail coverage rather than preserve stale IDs.

## JSON, images and files

JSON v9 follows ProjectBundle exactly; unsupported versions reject, no legacy conversion. Stable serialization uses canonical-json-v1; downloadable extension `.json`, MIME `application/json;charset=utf-8`. Project export announces that transient preferences/undo and bulk traces are excluded; run summaries and authored history remain included. Export to file does not mark imported evidence trusted on reimport.

SVG/PNG retain existing safe diagram behavior, updated to an explicit authored view. Configuration and measurements export only when already intentionally visible in that view; no hidden credential/provider fields. XML escape all text; no remote images/fonts/scripts, raw HTML or event handlers. SVG remains vector; PNG bounds <=8192px/side and <=16 million pixels. Validate extents/empty view before allocation; include clear too-large recovery. Revoke object URLs. Download filename stem comes from a bounded ASCII-safe title (fallback `system-studio`), never directory syntax. Existing `src/export/diagramSvg.ts` and `downloadDiagram.ts` are source evidence, not automatic acceptance for new view semantics.

## CSV v1

Export one explicitly selected immutable saved run (including imported/partial runs with provenance/status), not mutable editor state. Snapshot labels come from that run. If run has no metrics, explain “No measured metrics for this run”; do not download empty fake results. Logical runs can export measured counts, but no synthesized elapsed time/latency/rate.

Fixed columns in this order: `run_id,scenario_id,fingerprint,provenance,run_status,check_status,scope,element_id,element_label,metric,value,unit,available,reason,sample_start_ms,sample_end_ms`. One row per actual summary metric. `scope` is `root`, `message` or `element`; root/message rows have empty element fields. Whole-run summary only initially, not raw trace/time-series. Check status is `passing`, `failing`, `no-checks` or `incomplete`. Missing metric value is empty with available=false and reason; never zero. A real zero is value `0` with available=true. Units: `count`, `ms`, `requests/s`, `ratio`; logical sample times empty. Utilization is ratio, not formatted percentage. Numeric values use finite locale-independent decimal output; source summary explicitly defines denominator/window. Counts exclude producer acknowledgements unless metric explicitly named acknowledged.

UTF-8 BOM, comma delimiter, CRLF row endings, final CRLF. Quote every cell with `"`; embedded `"` doubles. Keep Unicode; text CR/LF/tab controls become visible spaces in CSV text cells (JSON preserves exact text). Numeric columns serialize only validated numbers/booleans, never user-supplied numeric strings. For **all text columns**, prefix ASCII apostrophe before quoting when the first non-whitespace code point is `=`, `+`, `-`, `@` or fullwidth U+FF1D, U+FF0B, U+FF0D, U+FF20, or the original contains leading CR/LF/tab controls; this is an explicitly lossy spreadsheet-oriented safety encoding. A user's leading apostrophe remains literal otherwise. Display export note: “Spreadsheet-safe text; use JSON for exact text.” Do not claim this is safe after arbitrary spreadsheet re-save/reinterpretation. [OWASP CSV Injection](https://community.owasp.org/attacks/CSV_Injection) explains formula triggers and application-dependent defenses; implementation QA must test the chosen encoding in target spreadsheet readers and strengthen it if needed before release.

CSV has <=100,000 rows and <=16 MiB output; compute size/limits before Blob allocation. Test hostile labels including separator+quote+formula, whitespace prefixes, fullwidth forms, multiline text, leading apostrophe, emoji, negative numeric measurements and unavailable metrics. No formulas or formula hyperlinks are emitted. Download extension `.csv`, MIME `text/csv;charset=utf-8`.

CSV enums are exact: `run_status=completed|invalid|failed|cancelled|incomplete`; `provenance=local|imported-unverified`. Export a stored terminal run only, not live partial batches. Partial stored runs retain their actual terminal status and unavailable metric reasons.

## Mermaid v1

Output plain text `flowchart LR` only; no renderer dependency is needed for download. Selected view elements sorted by stable ID map to generated `n0`, `n1`, …; groups to `g0`, `g1`, … independent of labels. Emit each node once using `n0["encoded label"]`. Wholly represented non-overlapping view groups emit `subgraph g0["encoded label"]` then member declarations and `end`; emit all edges after all node/subgraph declarations. Empty view rejects with “Add an element before exporting.”

Behavioral connections whose endpoints are placed emit `n0 -->|"encoded kind: label"| n1`. Descriptive/contains/deployed-on relations emit dotted `n0 -.->|"encoded kind: label"| n1`; containment arrows are descriptive here, never inferred nested execution. Omit colon suffix for empty label. Sort emitted edges/relations by stable ID. Subgraphs always emit at top level, never nested. One-level view groups are supported; if a future imported schema could express overlap/nesting, validation rejects the unsupported schema rather than silently emitting invalid nesting. Structural contains relationships remain labelled arrows and do not create duplicate Mermaid subgraphs.

Encode labels by Unicode code point: preserve ASCII letters/digits/space and non-ASCII letters; normalize CR/LF/tab to spaces; encode every other punctuation/control code point using Mermaid decimal entity syntax `#NN;` (including `#`, quote, backtick, brackets, pipe, semicolon, angle brackets, ampersand). Reject invalid surrogates at schema validation. This prevents source labels from becoming directives/edges/HTML. Never emit click links, Markdown labels, initialization directives, styles or raw HTML. Mermaid's official [flowchart escaping syntax](https://mermaid.js.org/syntax/flowchart.html) is the syntax authority; implementation must parse adversarial golden outputs using a pinned dev-only Mermaid parser and verify displayed label fidelity. A syntax promise without parser evidence is not acceptance.

Limitations shown before export: labels/directed relations/view groups only; excludes notes, coordinates/styles, ports/payload schemas, behavior/resources, scenarios, history and metrics. This is a lossy diagram and has no import/round-trip promise. Extension `.mmd`, MIME `text/plain;charset=utf-8`, UTF-8 without BOM, LF newline, final LF, <=2 MiB. Golden cases: `end` as label, quotes/pipes/backticks/entities/HTML-like strings, duplicate names, non-ASCII text, self-edge where legal, parallel port connections, wholly and partly represented groups. All source members stay unchanged.
