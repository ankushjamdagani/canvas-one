# Building with Canvas One composables

`apps/web` selects services and owns the existing Next.js routes and product interface.
`packages/*` owns reusable behavior and public contracts. History, storage, agents
and simulation have no mandatory product interface. Optional presentation is
exported separately. There is no shared contracts or miscellaneous runtime package.

| Package | Use it for |
| --- | --- |
| `whiteboard` | Versioned authored documents, atomic operations, one immutable document authority, extensions and editor contracts |
| `editor-reactflow` | The current editor implementation and engine-specific React bindings |
| `react` | Independent boards, custom rendering and instance-local runtime/portal hooks |
| `components-basic` | Text, shapes, images, frames and freehand point data, planners and optional renderers |
| `system-design` | System semantics, catalog, ports, drafts, scenarios, placements, custom components and session orchestration |
| `playback` | General tracks and animation transport with an injected clock and explicit provenance |
| `simulation-system-design` | Compiler, kernel, runner, recording queries and artifacts; optional simulation-gated history and archive compositions |
| `history` | Local undo/redo, version mechanics, merge ancestry, candidates and publication authority |
| `storage` | Atomic backend/coordinators, CAS, immutable receipts/rows, preferences, accounting, artifacts and pruning |
| `storage-indexeddb` | The IndexedDB implementation over the existing database schema |
| `commands` | Action registration, discovery, validation, availability, execution and cancellation |
| `agents` | Review queues, detached previews, bounded context and host model-provider contracts |
| `agent-bridge` | Paired browser/CLI relay over authenticated loopback sessions |
| `cli` | Local CLI and MCP tool clients/server |
| `collaboration` | Provider, presence, participant and concurrency contracts for future hosted synchronization |
| `ui` | Foundation controls, styles, tokens and assets |

Use package exports, declare workspace dependencies and keep TypeScript references
aligned. `npm run build:packages` builds the dependency graph in order;
`npm run check:packages` rejects source-path bypasses, cycles and forbidden headless
imports. `npm run check:headless-consumer` packs and installs a separate consumer
without React, Next.js, Dexie, React Flow or DOM globals.

## Compose the complete app

`createStudioComposition` selects repository boot, editing sessions, versioning and
execution leases. It accepts host model providers, trusted extensions, per-session
command contributions, renderer factories and an alternative canvas host. Pass the
composition to `CanvasOne`. The application supplies presentation and binds
namespace, build-version, error and recovery policy to package-owned services.

The complete workspace retains its system document as the authored format. Its
whiteboard runtime is the sole document authority; the system-design projection
into `BoardDocument` is read-only. Custom content lives in namespaced
`Element.component` records, with optional authored `Document.extensions`. These
values survive persistence, history, archives and explicit merge resolution. Purely
visual data is excluded from execution fingerprints. Existing immutable historical
payloads and hashes are retained.

For editable custom UI, use `createSystemDesignPresentation({session})` to bind
instance-specific semantic planners and `session.apply`. Presentation overrides
cannot replace built-in semantic identifiers. Register custom schemas/validators
and components through `extensions`; missing renderers display placeholders.
The same components become discoverable to agents. Oversized or unavailable
schemas are reported as `null` and are not generated by the diagram tool.

`createCommandContributions({session})` returns command definitions with an optional
explicit JSON palette input. The existing Cmd+K/F2 interface discovers and executes
these through its per-instance registry. A command needing a custom form stays
disabled in that interface until its host supplies the input UI.

## Embed an independent board

Create a `BoardRuntime<BoardDocument, BoardRecordMap>` with the neutral validator,
record reducer and lookup. Supply the actor for authored gestures and omit it for a
read-only presentation. Use `Board` with your adapter/host, or `ReactFlowBoard` from
the optional `/reactflow` entry. Supply custom renderers separately from semantic
data. Storage, simulation, routing and project navigation are optional.

The host owns runtime disposal. Board hooks provide its runtime, immutable snapshot,
actor and mounted portal target. Each board has its own selection, viewport and
portal scope. Alternate adapters provide geometry and gestures through the neutral
editor contract; unsupported capabilities return explicit results. Replacing an
engine still requires suitable renderers and a host implementation.

`examples/next-host` tests both the complete app and independent boards. The full
app build artifact exposes `CanvasOne` at its root and independent `/board` and
`/reactflow` entries. Use `/board.css` for generic board styles or `/reactflow.css`
for the default engine; `/styles.css` retains the full-app stylesheet. See
[embedding.md](embedding.md) for packaging commands.

## Work with an agent

```sh
npm run build:packages
node packages/cli/dist/main.js bridge --origin http://localhost:3000
```

Open AI collaboration through the workspace toolbar or Cmd+K. Pair using the printed
address and short-lived code. Keep the separate agent token in the CLI environment,
outside project documents:

```sh
export CANVAS_ONE_BRIDGE_URL=http://127.0.0.1:47831
export CANVAS_ONE_AGENT_TOKEN='the-token-printed-by-your-local-bridge'
node packages/cli/dist/main.js call board_inspect
node packages/cli/dist/main.js call component_schemas
node packages/cli/dist/main.js mcp
```

Use the actual bridge URL printed at startup if it differs. `diagram_create` accepts
readable component aliases, optional automatic positions, custom component data,
connections and annotations. Use the schema returned by `component_schemas` and
scope/revision returned by `board_inspect`. Agents submit no snapshots or receipts.
Repeated requests retain their generated IDs; changed payloads require a new
operation ID. Preview projection is detached and never writes. Human acceptance
applies one validated transaction and one undo step; stale proposals require a new
review. CLI/MCP forwards to the browser and never writes IndexedDB independently.

Secure browser origins may require local-network permission. Exact allowed origins,
paired session tokens and expiration checks remain enforced. MCP cancellation keeps
the server responsive; cancelling a request does not undo an already reviewed write.
Model clients and credentials are supplied by the host.

## Scope of this release

Existing authoring, history, persistence, linked projects, simulation, transfers and
routes remain part of the complete app. General playback reports authored/example
or recorded provenance and does not manufacture measurements. The existing system
engine is preserved; realistic calibration still needs workloads, explicit
assumptions, repeated seeded runs and comparisons with measured load tests.

Hosted human invitations, roles/conflict resolution, Git synchronization, untrusted
plugin distribution/sandboxing, interactive freeform tools and codebase architecture
generation remain future work. Their contracts are extension points, not claims of
implemented hosted collaboration or a complete multiplayer protocol.
