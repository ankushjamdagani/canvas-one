# System-design simulation

`./archive` owns the current v9 system-design archive schema, iterative raw-input guards, full document/history/reference/evidence validation and canonical export/hash generation. Hosts inject consistent revision-checked archive reads, ID issuance, limits and error policy. Portable row stripping and the consistent-reader contract come from generic storage; neither the codec nor its generic storage dependency imports Dexie or UI. Unsupported versions remain rejected. Snapshot hashes, history IDs and run summaries/provenance are retained; export excludes local namespaces, receipts, preferences and trace bytes. Import namespace allocation and trust downgrading remain the host's atomic storage write policy.

`./history` is an optional, headless composition for the current system-design workflows that require simulation evidence before commits and publications. It owns the full history and publication controllers, observable workflow state, candidate review, conflict resolution, scenario status derivation and evidence gates. Hosts provide narrow session, history storage and candidate authority ports plus a storage error policy. No React components or database implementation are imported; apps render their own interfaces. The generic `@canvas-one/history` remains usable without simulation, and system-design semantic diff/filter helpers live in their domain package.

`./candidate-execution` dispatches compilation, candidate runs and artifact persistence through a narrow artifact store and optional execution provider. It keeps evidence tied to the original immutable snapshot and reports candidates superseded while running. History does not import this implementation; hosts select it when candidate execution is needed.

Headless scenario compiler, deterministic runner, resource kernel and recorded result contracts. Depends on system-design semantic snapshots; presentation and worker hosting are supplied by consumers. Existing engine algorithms and recording formats are preserved.

`@canvas-one/simulation-system-design/playback` exports the existing `PlaybackStore`, cycle/overlap indexes, flash/traffic projections, interval statistics and cycle timeline density layout. The store has no timers: hosts call `advance(realDtMs)` and supply their own clocks. It reconstructs recorded facts at a playhead and retains the same live-history eviction behavior; it does not invent simulation measurements.

Each implementation also has an explicit `playback/*` export. General timeline gestures and activity presentation contracts come from `@canvas-one/playback`, keeping React and editor engines outside the recording package.

`./controller` owns the execution, scheduling, worker lifecycle and one-time artifact persistence controller. Supply a `RunArtifactStore`, transport and ID issuer, with optional clock, build versions and storage error policy. `./artifacts` owns run records and save contracts. `./token` owns the single in-memory token issuer used by both execution and persistence; serialized copies cannot forge local run provenance. The app supplies its database error policy and builds its inspector UI independently.
